# 황다연 | EY한영 감사부문 포렌식팀 포트폴리오

정보보호를 주전공하고 개인정보보호를 복수전공하고 있습니다. 동의ON에서 기업별 필수 동의 항목과 이용자의 선택 내역을 조회하는 API를 구현했습니다. Windows 악성코드 분석 과제에서는 로그온 시 다시 실행되는 조건과 외부 접속을 시도하는 코드를 추적했습니다.

## 동의ON - 필수 동의와 이용자가 선택한 항목 조회

4인 팀의 팀장으로 개발 일정을 조율하고, 개인정보의 민감도와 외부 제공 여부, 보유기간 등을 반영하는 위험도 계산을 구현했습니다. 조회 API에서는 회사가 제시하는 필수 동의항목과 이용자가 실제로 선택한 항목을 구분해 반환했습니다. 화면에 표시할 체크 상태와 계산에 필요한 변수가 같은 항목에 연결되는지 테스트했습니다.

공용 모델에서는 점수의 등급 경계와 필드 누락, 잘못된 입력값을 점검하고 계산 결과를 저장할 때 생긴 자료형 불일치를 수정했습니다. PR #20에는 당시 공용 모델 테스트 28개 통과 기록이 있습니다. #21에서는 동의항목 조회 관련 테스트 3개가 통과했습니다.

이 프로젝트의 사용자 실험을 다룬 논문은 정보보호학회논문지 게재 허가를 받았습니다.

- [공용 모델 위험도 계산과 회귀 테스트 - PR #20](https://github.com/dayeon053/dynamic-consent-system/pull/20)

## Windows 악성코드 - 실행 조건과 통신 경로 분석

개인 기말과제에서 프로세스 목록을 읽는 코드와 로그온 시 다시 실행되도록 등록하는 예약 작업을 살펴봤습니다. 문자열을 복호화해 얻은 명령제어 서버의 접속 정보를 Winsock 초기화, 소켓 생성, 연결 재시도 코드와 대조했습니다. 어떤 조건에서 외부 접속을 시도하는지 9쪽 보고서에 정리했습니다. 실제 접속 성공이나 데이터 유출을 확인하려면 통신 기록이 추가로 필요합니다.

## LogosFuzz - 크래시 20건 검토와 컴파일 옵션 누락 수정

Hopper에서 발생한 크래시 중 제가 맡은 20건은 호출부 코드와 입력값, 빌드 옵션, 실행 로그를 대조하고 Docker에서 반복 실행했습니다. 팀의 후속 검토에서 일부 판정이 달라져 실제 결함 수는 확정하지 않았습니다.

별도로 C/C++ 파일마다 적용된 컴파일 옵션을 추출해 하네스 생성에 연결했습니다. libsndfile 1.2.2를 분석할 때는 비교 기준을 만드는 단계에 헤더 검색 경로가 전달되지 않아 92개 파일 중 70개가 컴파일에 실패했습니다. 파일별 옵션을 이 단계에도 전달하도록 수정한 뒤 92개 파일을 컴파일하고, 선정한 API 8개의 분석 결과를 대조했습니다. 수정 내용과 검증 기록은 아래 두 PR에 있습니다.

- [범용화 개발 브랜치](https://github.com/sesezz/LogosFuzz/tree/feature/generic-embedded)
- [대상 프로필과 파일별 빌드 정보 추출 - PR #71](https://github.com/sesezz/LogosFuzz/pull/71)
- [지식베이스 연결과 비교용 컴파일 옵션 수정 - PR #76](https://github.com/sesezz/LogosFuzz/pull/76)

## 가짜 금융 앱 - 의심 판정의 근거와 검증 범위

6인 팀을 구성하고 악성 APK 탐지 실험과 결과 검증을 맡았습니다. 정상 금융 및 결제 앱 5개와 공개 APK 4개에서 금융기관 사칭 키워드, 권한 조합, 패키지명을 살폈습니다. 공개 APK 4개의 실험 결과는 악성 의심 2개, 주의 1개, 정상 1개였습니다. 실험 조건과 분류의 근거를 팀원들과 논문 형식의 원고로 정리해 공모전에 제출했습니다.
